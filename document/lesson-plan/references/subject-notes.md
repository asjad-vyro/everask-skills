# Subject notes

Read only the section for the lesson's subject. These are design notes, not curriculum content: take the topic's facts from the user and from well-established knowledge, and keep every example correct.

## Maths

- Start the launch with a concrete problem or picture students can attempt before being shown a method.
- Use a visual model suited to the topic (number line, bar or tape diagram, area or array model, table, graph) in the worked example: the script says what the teacher draws on the board. On the handout, build it from table cells (for example a bar split into equal cells) or leave a labelled space for students to draw it; no generated images. A filled-in reference table that shows the answers stays on the teacher's side.
- Plan problem variety deliberately: list the easy case every student must manage, the typical case, and the hardest case students commonly get wrong for this topic. Each of these appears as a numbered problem on the handout or as the exit ticket. A case named only in the plan's prose is not covered.
- Never put the hardest case only in an optional extra, and never drop the easy case: an all-hard set fails as much as an all-easy one. If the topic includes fractions, decimals or negative numbers, at least one required problem uses them.
- Choose the exit ticket so that a student holding the most likely misconception gets it wrong. If that student would still get it right, it checks nothing: swap it.
- If a task has more than one correct answer or method, say so in the plan so the teacher accepts all of them.
- For younger children use real objects or paper cut-outs and keep wording minimal. Ask for an explanation ("how do you know?") on one task only, with a sentence starter.
- Work every problem in `execute_code` (use Python's `fractions` module for fractions) and put the answers in the key.

## Language and reading

- Name the text. If the user gave one, use it. If not, write a short original passage and mark it as written for this lesson, or name a published text (title, author) for the teacher to supply. Never reproduce a published text from memory, even a public-domain one; quote it only if you opened it with `web_extract`, and then only a short passage.
- Include a vocabulary step: three or four words taken from the text, with the sentence they appear in.
- Questions should need evidence from the text ("what in the text tells you?"), not opinion alone. Go from a literal question to an inference question.
- In discussion, students write a short answer before they talk to a partner, so every student has something to say.
- Early readers in a language written with an alphabet: word work and practice text use only letter-sound patterns already taught; students sound words out rather than guess them from a picture or the first letter; the teacher says dictation words aloud and they are not printed on the child's page; the exit check is reading a few target words aloud.
- Writing lessons: model one short piece, give a frame, then students write a short piece; the check is a named look-for such as "has a claim and one reason".

## Science

- Open with a phenomenon or question students can observe or predict (a demonstration, a picture, a short measurement).
- Students predict, observe or collect data before the teacher explains; the teacher does not give the explanation first.
- Include a prediction or claim, an observation or data step, and an explanation that uses the evidence ("claim, evidence, reasoning" fits older students; younger students draw and say).
- Say what the teacher demonstrates versus what students do, and flag any safety point. Prefer household or classroom materials.
- Name the usual misconceptions for the topic and plan a question that exposes each.
- The exit ticket asks students to explain a new, small example of the same idea, not the one they investigated.
- If data or calculations are used, compute them in `execute_code`.

## Humanities (history, geography, civics, economics)

- Frame the lesson around one answerable question.
- Use one or two sources, labelled Source A and Source B, each with title, author or creator and date. Use only sources you are sure exist. Quote a source word for word only if the user gave it or you opened it with `web_extract`; otherwise name it and say where the teacher finds it. A passage you paraphrase or write for the lesson is labelled "adapted from <source>" or "written for this lesson", never presented as a quotation. Only give a link if you opened it with `web_extract` and it works.
- Sequence: short background from the teacher, then source analysis with two or three questions that move from observe, to who made it and why, to compare with the other source. Each question names the source it is about (Source A, Source B or both). Then a discussion and an exit ticket.
- The exit ticket answers the lesson's question with a claim and one or two pieces of evidence from the sources, sized to its minutes; never a take-home essay.
- Keep the content to the region, period and terms the user named. Check dates and names; for any date or figure not given by the user, state it only if you are sure, otherwise leave it out.
