# Skeletons for official documents

These are common administrative practice, not law. Offices differ. A previous document from the user's own organisation always overrides anything here. Every `<...>` is filled from what the user gave, or becomes a visible placeholder in the document's language (for example `[nomor]`, `[number]`, `[번호]`, `[编号]`). Never invent a legal basis, regulation number, article number, name or title.

Find the section for the document's kind and language. If the language or kind has no section, use section 1 and a neutral formal register of that language, and say so in the assumptions line.

## 1. Generic memo, circular, notice or internal regulation (any language)

Memo (internal, one issuer to staff):
1. Organisation name (letterhead line).
2. Document type: MEMO (in the document's language).
3. Number (placeholder unless given), date.
4. To, From (name and title), Subject.
5. Body: purpose in the first sentence; what changes or what is required; from when it applies (effective date as given); who to contact.
6. Numbered points when there are three or more separate requirements.
7. Signature block: title, name; then Distribution (the groups named by the user).

Circular or official notice (to many readers, from an organisation):
1. Organisation, document type (CIRCULAR or NOTICE), number, date.
2. Subject line.
3. Opening line saying why it is issued, then numbered points, then the effective date, then the contact.
4. Signature block, distribution list.

Internal regulation (rules inside an organisation):
1. Title, number, date.
2. Chapter I: purpose and scope (who and what it covers). Chapter II onward: the rules, grouped by topic, in numbered articles, one rule per article, "must" for obligations and "may" for permissions.
3. Final chapter: effective date, how it is changed, what it replaces if the user said so.
4. Approval line and signature block.

## 2. Indonesian: Surat Keputusan (SK)

Order, as commonly used by Indonesian schools and organisations:
1. Kop surat (letterhead): the issuer's name as the user gave it, with placeholders for address and contact. Do not add a ministry, government body or foundation name the user did not give.
2. `SURAT KEPUTUSAN <jabatan pembuat keputusan>`, then `NOMOR: [nomor]`, then `TENTANG <judul>`.
3. The issuer's title in capitals followed by a comma.
4. `Menimbang:` lettered items a., b., each starting `bahwa`, giving the reason. Restate only the need and purpose the user gave (for example that a committee is needed for the event they named); add no general claims about benefits.
5. `Mengingat:` numbered items 1., 2. giving the legal or internal basis. Use only bases the user gave. If none was given, write one line `1. [dasar hukum / peraturan yang berlaku]` and list it among the placeholders.
6. Optional `Memperhatikan:` for a proposal, meeting or letter the user mentioned.
7. `MEMUTUSKAN:`, then `Menetapkan:` with the title of the decision, then the operative parts labelled `KESATU:`, `KEDUA:`, `KETIGA:` and so on. KESATU states what the title says (names and roles in a table). Further dictums only for what the user gave (for example duties, the dates of the event, the budget source or `[sumber dana]`). A closing dictum often says the decision applies from the date it is issued and will be corrected if a mistake is found.
8. `Ditetapkan di [kota]` and `pada tanggal [tanggal]` (placeholders unless given), then the issuer's title, space for signature and stamp, the full name, and NIP only if the user gave it.
9. `Tembusan:` numbered list of copies, only if the user named recipients.

Other Indonesian kinds: Surat Edaran (circular): letterhead, `SURAT EDARAN`, `Nomor: [nomor]`, `Tentang: <hal>`, a short opening, numbered points, place and date, signature, `Tembusan`. Surat Tugas (assignment letter): letterhead, `SURAT TUGAS`, number, "Yang bertanda tangan di bawah ini" with the issuer's name and title, "menugaskan kepada" with the assigned person's name, title and the task, place and date, signature.

## 3. Korean administrative documents (공문서, 기안문 style)

Common structure in Korean public bodies (the 행정업무운영편람 describes it in detail):
1. Header: organisation name (기관명).
2. `수신` (recipient; `내부결재` for an internal approval).
3. `제목` (subject): one line stating the matter.
4. Body: items numbered `1.`, then `가.`, then `1)`, then `가)`. A single item is not numbered. Short opening sentence, then the matter, then the request or instruction.
5. `붙임` (attachments) with the names the user gave: `붙임  1. <name>  1부.`
6. `끝.` after the last line of the body, or of the attachment list when there is one.
7. Issuer line (발신명의: the head of the organisation) and the 시행 line (number and date of issue). Fill only what the user gave; the rest is a placeholder such as `[시행 번호]`.
Style: formal polite written endings (`~합니다`, `~바랍니다`, `~하시기 바랍니다`). Dates in the form `2000. 1. 5.` (full stop after each part, no leading zero) only when the user gave them; copy the user's form.

## 4. Chinese administrative documents (公文)

Common structure, following the 党政机关公文 layout (GB/T 9704 sets the national format for party and government bodies; other organisations often imitate it and may add their own rules):
1. Header: issuing organisation, and the document number `发文字号` in the form `<机关代字>〔<年份>〕<序号>号`; use placeholders unless given.
2. Title: `<发文机关>关于<事由>的<文种>`. Common kinds (文种) include 通知 (notice), 通报 (bulletin), 决定 (decision), 请示 (request for instructions), 报告 (report), 函 (letter between offices), 纪要 (minutes), 意见 (opinion).
3. 主送机关 (main recipient), followed by a colon.
4. Body (正文): reason for the document, then the matter in numbered points (`一、` `（一）` `1.` `（1）` as the levels go down), then requirements and the effective date.
5. 附件 line if there are attachments, naming them.
6. Issuer signature (发文机关署名) and the date of the document (成文日期: year in full, month and day without a leading zero, as the user gave them).
7. 抄送 (copies) if the user named recipients.
Style: formal, concise written language; `特此通知` closes a 通知 when natural.

## 5. Spanish: resolución (Latin American style)

Common in Latin American administrations (Spain's administration uses other headings, such as antecedentes, fundamentos de derecho and resuelvo; say in the assumptions line that this follows the Latin American form):
`RESOLUCIÓN N.º [número]`, place and date placeholders, `VISTO:` (what prompted it), `CONSIDERANDO:` (the reasons, as paragraphs), `RESUELVE:`, then `Artículo 1.º`, `Artículo 2.º` for the operative parts, a final article on when it takes effect, signature block. Use only grounds the user gave; do not cite laws unless the user did. For a Spanish memo, circular or notice use section 1 with `Para:`, `De:`, `Asunto:` and `Fecha:`.

## 6. Portuguese: portaria (Brazilian style)

`PORTARIA Nº [número], DE [data]`, an ementa (one line saying what it does), the issuer's title followed by a line that the issuer acts within their powers (as the user described; cite no law unless given), `RESOLVE:`, then `Art. 1º`, `Art. 2º` for the operative parts (`Art. 10.` and up without the ordinal sign), a final article on when it takes effect, local and data, signature. For a memo, circular or notice use section 1 with `Assunto:`. Portuguese used in Portugal has its own conventions: use section 1 and say so.

## 7. Russian: приказ

Common layout (ГОСТ Р 7.0.97-2016 describes the details): organisation name, `ПРИКАЗ`, date and number (placeholders unless given), place, a title starting with `О` (for example "О введении ..."), a short ground paragraph, then `ПРИКАЗЫВАЮ:` followed by numbered points, one action and one responsible person or group each; a point on who controls execution only if the user named someone; then the title, signature and full name of the head. If the user asks for staff to be acquainted with the order, add the line `С приказом ознакомлены:` with space for names.

## 8. French, Arabic, Turkish and other languages

No fixed skeleton here. Use section 1 in the formal administrative register of that language (for example for French a `NOTE DE SERVICE` with `Objet :`; for Arabic right-to-left layout; for Turkish a `GENELGE` or `DUYURU` with `Konu:`). State in the assumptions line that the user's own earlier document would give a closer match, and keep to what the user gave.
