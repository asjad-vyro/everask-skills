# Report types and their sections

Use the kind the user names. If the user's institution gave a template or section list, use that instead and map the content onto it. Translate headings into the report's language. Every section is built only from the user's notes; where notes are missing, write `[to complete: <what>]`.

## Internship or practice report

1. Title page: title, student name, programme, institution, host organisation, supervisor(s), internship dates, submission date.
2. Acknowledgements (only if the user wants them; short).
3. Summary (about 150 words, written last).
4. Introduction: purpose of the internship, host organisation, period.
5. About the organisation: what it does, its structure and the department where the intern worked, as given.
6. Tasks and activities: by period or by task; what was done, tools used, outputs.
7. Skills and learning: what was learned, linked to the tasks.
8. Challenges and how they were handled.
9. Conclusion and recommendations.
10. Appendices (list only what the user mentioned).

## Activity or event report

1. Title block: activity name, date(s), place, organiser.
2. Background and purpose.
3. Participants: who took part and how many, as given.
4. Programme or description of what happened, in time order.
5. Results and outcomes against the aims.
6. Problems met and lessons.
7. Recommendations or follow-up.
8. Budget or costs, only if given.
9. Attachments: photos, attendance list, if mentioned.
10. Signature block: prepared by, approved by, as `[to complete: ...]` when not given.

## Project completion report

1. Title block: project name, owner, sponsor, period, report date.
2. Summary.
3. Background and objectives.
4. Scope: what was delivered, what was not.
5. Timeline: planned versus actual, as given.
6. Budget: planned versus actual, as given; sums computed in code.
7. Results and deliverables against the objectives.
8. Issues, risks and how they were resolved.
9. Lessons learned.
10. Next steps and handover.

## Lab report

1. Title and details: experiment name, name, group, date, instructor.
2. Aim (or objective).
3. Theory (short, only what the user gave or standard definitions you are sure of).
4. Apparatus and materials.
5. Method: numbered steps in past tense.
6. Observations and data: the user's measurements in a table. Never invent or adjust a measurement.
7. Calculations: every calculation in `execute_code`, with the formula shown, the values substituted, units, and the result. Say how many significant figures were kept.
8. Results.
9. Discussion: compare results with the expected value only if the user gave one; sources of error that follow from the method described; do not invent errors.
10. Conclusion: one short paragraph answering the aim.
11. References: only what the user gave.

## Field visit report

1. Title block: site, date, purpose, who visited.
2. Objectives of the visit.
3. Description of the site and organisation, as observed or given.
4. Activities and observations, in time order.
5. Findings: what was learned, linked to the objectives.
6. Problems or limits of the visit.
7. Conclusion and recommendations.
8. Attachments mentioned (photos, permits).

## Incident report

1. Title block: incident type, date and time, location, reporter, report date.
2. People involved and witnesses (names only as given; roles).
3. Description: a factual, time-ordered account. No blame, no opinion, no guessing at causes the user did not state.
4. Injuries, damage or losses, as given.
5. Immediate actions taken, by whom, when.
6. Cause (stated only if known, otherwise `[to complete: cause under investigation]`).
7. Follow-up actions and who owns them, as given.
8. Notifications made (who was told), as given.
9. Signature block: reporter, reviewer, as blanks when not given.
