# Influencer Campaign Brief

A good result is a one-to-two page brief a creator can act on without a call. It reflects the signed deal exactly, locks the facts (offer, claims, disclosure) and leaves the voice (hook, pacing, setting, delivery) to the creator. The finished brief goes in the reply itself, in full.

## Hard rules

- The signed deal wins. Use the user's deliverables, fee, usage rights, code and revision-round count exactly as given. Never add, drop or change one. If the user's own details contradict each other, say so in a short "Flags" note and follow the deal terms.
- Invent nothing: no dates, names, codes, prices, claims, proof points, metrics or creator history that the user did not give. Write `not given - add before sending` or mark an assumption. Never put a fabricated "proof" behind a key message; if no proof was given, write `proof needed from the brand`.
- Never restate or set usage rights, exclusivity or payment terms. Point to the signed agreement. The `Rights and payment` section reads only `Per the signed agreement.` with no durations, scope, channels or fee. Usage durations and scope (for example "60 days organic") also stay out of the Context line, the paid-media line and every other part of the brief.
- Never assert a deal term the user did not give (for example "raw files: not part of this deal"). Leave it out or write `not given - confirm`.
- Never script the creator's words, camera work, cuts or music. Only legally required or offer wording is verbatim.
- Do not ask questions first. Decide, state assumptions, and deliver. Use `clarify` only if the user gave no brand, product or platform at all.
- This is a draft for the brand to review, not legal advice. Disclosure rules differ by country and platform; for a named market, make at most one `web_search` for the current rule and link it.

## Step 1: Pull the facts

List what the user gave: brand and product, creator and platform, campaign goal and metric, deliverables, fee and rights terms (for reference only), revision rounds, dates, code or link, claims and proof, no-go topics, paid-media plans, B2B or B2C. Anything missing becomes `not given` or a labelled assumption. Keep this list in your head; do not output it.

## Step 2: Reconcile with the deal

Check deliverable counts, durations, rounds and dates against each other. A contradiction (for example "2 rounds" in one place and "unlimited" in another, or a posting date before the draft date) goes into the Flags note. Do not fix it silently.

## Step 3: Choose the angle

Pick one message angle yourself and say why in one line. Base it on what the user told you about the creator's content and audience; never on generic brand copy. If you know nothing about the creator's content, say the "Why you" lines are a placeholder for the brand to complete. Offer one alternative angle in a single line under the brief, not before it.

## Step 4: Set the freedom level and state it

- Default: **high**.
- **Medium** if it is a first collaboration or the creator is new to the category.
- **Low** only if the metric is a redemption or signup count and the offer must land verbatim, or a regulated category forces script approval. Low is off the table when the deal includes one revision round or fewer: say why.
- Regulated categories (health, finance, supplements, security) need claims checked by legal before the brief goes out. Say so in the brief's review section. Only these four count. Do not call another category (for example food or beauty) regulated; prohibiting health claims there is a no-go rule, not a legal-review trigger.

Name the condition that moved the level off high.

## Step 5: Write the brief

Read `references/brief-template.md` and fill it in. Read `references/guardrails-and-specs.md` when you write the deliverables table, the paid-media line, the disclosure section and the prohibited-claims list. Rules for the content:

- Three key messages at most, each with its proof. Take each message only from a claim or point the user supplied. If the user gave two, write two. Never add a message to fill a slot.
- Every item is either a non-negotiable or a preference. Nothing floats between.
- Every deliverable carries format, count, length, aspect ratio (visual formats), link or code mechanism, draft deadline and posting window. Where the user did not give one, write `creator's choice` only if it is deliberately open, otherwise `not given - confirm`.
- Disclosure is its own section: required wording, placement per format, the platform's branded-content tool, who verifies after posting. If the user gave no wording, use `#ad` or `Paid partnership with <brand>` as the default and say it is a default.
- Declare paid-media intent now in one of these forms only: `No paid amplification planned`, `Organic only per the agreement`, or `Paid amplification possible per the agreement`. Never include durations or scope. If amplification is possible, tell the creator to use licensed audio. Otherwise make no audio ruling.
- Do not invent specs or deadlines the user did not give, such as on-screen durations for a code ("at least 3 seconds") or verification windows ("within 24 hours"). Leave them out or label them `suggested`.
- Review rounds equal the deal's count. Give the number the user gave; if none, `not given - add the deal's count`.
- Tracking: code, tracked link or landing page, to be live and tested before the posting window.
- Keep only the five to ten brand rules that matter for this content type. Do not paste a style guide.
- Dates: use the user's. If none were given, give relative milestones ("draft due 7 days before the posting window") and mark them as a suggested schedule.

## Step 6: Check, then reply

Before replying, confirm: deal terms match; no usage duration, scope or fee appears anywhere in the brief and `Rights and payment` reads only `Per the signed agreement.`; no unsupplied deal terms, specs or deadlines are stated unless labelled `suggested`; every key message traces to a claim the user gave; every item is locked or open; no scripted lines outside legal or offer wording; every deliverable has all its fields; disclosure has its own section; at most three messages, each with proof; the brief would not work for any other creator (the "Why you" section names something specific the user gave, or is flagged as needed); no invented facts; no leftover `<angle brackets>`.

Reply in this order:

1. The brief, in full, following the template headings.
2. `Flags and assumptions`: bullet list of contradictions, anything marked `not given`, and each assumption.
3. `Alternative angle`: one line.
4. `After it goes live`: one line naming who verifies disclosure (the person the user named, or "the brand's partnerships owner" if not given).

Do not build a file unless the user asks for one. If asked for a .docx or PDF, load the built-in `docx` or `pdf` skill with `skill_view` and follow it. Never send the brief anywhere; it is a draft until the user says to send it.
